## 使用者、工作與情境

主要使用者是要登記請假的員工。課堂情境中，員工原以訊息提出申請，無法確認是否登記成功；這是教材設定，並非實際訪談證據，耗時與改善幅度未量測。

主流程：開啟頁面 → 下拉選擇員工 → 填假別、開始與結束日期、時段及選填理由 → 送出 → 顯示成功 → 在「我的假單」看到待審核申請（G-01）。重新整理並選回同一員工，仍能查到已保存的內容。

輸入不合法時，顯示可理解的錯誤，不新增假單；員工可修正後再送出（G-02）。送出期間顯示「送出中」並鎖住送出按鈕，收到結果後顯示成功或失敗。送出前離開頁面不構成提交；主線不提供已送出假單的撤回功能，也不承諾保存未送出的草稿。

## 故事與驗收條件

以下日期案例均為可重現的驗收例子，不是已執行的證據；每條案例中的其他欄位均合法。全文件共 3 個故事、10 項 AC。

### US-01 登記請假並得到送出回饋（G-01）

身為員工，我想填表送出請假申請，以便確認申請已登記。

- AC-01.1：Given 名單中存在員工 A，When 選 A 並送出 2026-10-12 當日整天特休、理由留空，Then 顯示成功，新增一張 A 的申請，保存所填內容，計算天數為 1，狀態為 `pending`（待審核）。
- AC-01.2：Given 驗收時的今天為 2026-10-14，When 送出 2026-10-12 當日整天事假，Then 不因日期已過而拒絕，成功新增一張待審核申請。
- AC-01.3：Given 已按下送出且尚未收到結果，When 再次點擊送出按鈕，Then 按鈕維持不可操作並顯示「送出中」，該次連點不造成額外送出；收到確定結果後結束送出中狀態，顯示成功或失敗。若網路中斷而無法確認結果，則解除按鈕鎖定，顯示「無法確認是否送出成功，請先查看我的假單，再決定是否重送」，不自動重送，也不宣稱未存檔。
- AC-01.4：Given 一張申請已成功送出，When 之後再次送出完全相同且合法的內容，Then 不以重複為由拒絕或合併，另新增一張待審核申請並顯示成功。

### US-02 不合法輸入得到說明且不存檔（G-02）

身為員工，我想知道輸入哪裡不符合規則，以便修正，避免錯誤申請被登記。

- AC-02.1：Given 員工、假別、開始日期、結束日期或時段有任一必填值缺少，或員工不存在、假別或時段不在允許值中，When 送出，Then 後端拒絕該申請，畫面顯示可理解的錯誤，假單筆數不增加；繞過畫面限制也不得存檔。
- AC-02.2：Given 新提交理由先去除前後空白後，以 Unicode 碼位計數（中間空白計入），When 送出「假」重複 100 次，Then 可成功保存處理後文字；When 分別送出 101、200、201 碼位，Then 顯示「理由最多 100 字」、拒絕且資料不新增或改寫。只含空白視為未填，空值合法；特殊字元計法不變。變更前已保存的 101–200 碼位理由保留原文，仍可依所選員工查閱，不截斷、不刪除。
- AC-02.3：Given 日期順序、時段與工作日符合下方規則表中的合法或拒絕案例，When 分別送出，Then 合法案例保存表列天數；拒絕案例顯示對應規則的錯誤且假單筆數不增加。
- AC-02.4：Given 申請因不合法輸入被拒絕且未存檔，When 員工修正錯誤後重新送出合法內容，Then 顯示成功且只新增此次合法申請，原先被拒絕的申請仍不存在。

### US-03 查看所選員工的假單（G-01）

身為員工，我想查看自己的申請與狀態，以便確認資料已保存並避免混淆其他人的申請。

- AC-03.1：Given A 與 B 各有已保存的假單，When 選 A 查看「我的假單」，並重新整理頁面後再次選 A，Then 兩次均能查到 A 的已保存申請，包含假別、日期、時段、理由、天數與待審核狀態，且不顯示 B 的假單；切換 B 時同理。
- AC-03.2：Given 員工 C 沒有任何假單，When 選 C 查看「我的假單」，Then 明確顯示目前沒有申請，不沿用先前員工的列表，也不因此新增資料。

## 產品規則與體驗

員工從名單選擇身分，不使用登入。假別只有 `annual`（特休）、`personal`（事假）、`sick`（病假）；時段為整天、上午或下午。申請成功代表已登記為待審核，不代表已核准。天數與新申請狀態由後端決定，不接受客戶端指定的天數或狀態作為存檔結果。

| 情境／規則 | 使用者看見的結果與資料變化 | 來源／AC |
|---|---|---|
| 新提交理由選填，最多 100 碼位 | 空值可送出；超長時拒絕且不新增。既有 101–200 碼位理由仍顯示原文。理由只作文字呈現。 | 本次變更決策、Brief D-01 修訂／AC-01.1、AC-02.2、AC-03.1 |
| 過去日期 | 接受補登，其他日期與時段規則仍須符合。 | Brief D-02／AC-01.2 |
| 送出中與重複內容 | 同一次送出期間鎖住按鈕；完成後再次送出相同內容可另建假單，不自動去重。 | Brief D-03／AC-01.3、AC-01.4 |
| 驗證失敗與修正 | 顯示可理解的錯誤；拒絕不新增，修正後可再送出。 | Brief G-02／AC-02.1～AC-02.4 |
| 資料持久性與所選員工 | 重新整理後選回同一員工可查到已存資料；只顯示所選員工的申請。 | Brief G-01、課程題目／AC-03.1、AC-03.2 |

日期包含開始與結束兩日，只計週一至週五；不另扣國定假日。整天每個工作日 1 天；上午、下午每次 0.5 天，且限單一工作日。以下為 AC-02.3 的邊界例子，各列獨立驗收：

| 輸入日期與時段 | 預期結果 |
|---|---|
| 2026-10-09（五）至 2026-10-12（一），整天 | 成功，2 天；週末不計。 |
| 2026-10-12（一）當日，上午或下午（分別驗證） | 成功，各 0.5 天。 |
| 開始 2026-10-13，結束 2026-10-12，整天 | 拒絕：結束早於開始；不新增。 |
| 2026-10-12 至 2026-10-13，上午或下午（分別驗證） | 拒絕：半天跨日；不新增。 |
| 2026-10-10（六）至 2026-10-11（日），整天 | 拒絕：沒有工作日；不新增。 |
| 2026-10-10（六）當日，上午或下午（分別驗證） | 拒絕：沒有工作日；不新增。 |

不自動去重是已確認的取捨：鎖按鈕降低連點，無法保證網路中斷後重送或不同操作不產生重複假單。連線失敗本身也不能證明後端未存檔；不將它與「後端驗證拒絕且不存檔」混為一談。
